## 1. 연구 개요

### 1.1 연구 목표

물류 창고에서 입고 제품의 **이미지만으로** 무게와 부피를 자동 예측하는 AI 시스템 개발 및 다양한 방법론 비교 평가.

### 1.2 연구 범위

| 항목 | 내용 |
|------|------|
| **예측 대상** | 무게 (g), 부피 (cm³), 카테고리 |
| **입력 데이터** | 제품 이미지 (1~3장) |
| **평가 방법** | 3가지 접근법 비교 |
| **테스트 데이터** | 물류공간 예측 데이터 100개 + Mercari 50개 |

## 3. 방법론 1: GPT Vision 기반 예측

### 3.1 시스템 구성

```
┌─────────────────────────────────────────────────────────────────────┐
│                      GPT Vision 예측 파이프라인                       │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   입력                   처리                       출력              │
│  ┌──────────┐    ┌─────────────────────┐    ┌─────────────────┐    │
│  │ 제품     │ →  │ Base64 인코딩      │ →  │ 카테고리        │    │
│  │ 이미지   │    │ + System Message   │    │ 무게 (g)        │    │
│  │ (1장)    │    │ + Few-shot 예시    │    │ 부피 (LxWxH)    │    │
│  └──────────┘    │ + 프롬프트         │    └─────────────────┘    │
│                  └─────────────────────┘                           │
│                           │                                        │
│                           ↓                                        │
│                  ┌─────────────────────┐                           │
│                  │   GPT-4o Vision     │                           │
│                  │   API 호출          │                           │
│                  │   (temperature=0.3) │                           │
│                  └─────────────────────┘                           │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 개발 과정

#### Phase 1: 초기 시스템 문제점 분석

| 문제 | 증상 | 원인 |
|------|------|------|
| 동일값 출력 | 항상 500g, 1200g 반복 | temperature=0.1 너무 낮음 |
| 이미지 분석 거부 | "Unable to identify" | 시스템 메시지 부재 |
| 낮은 정확도 | 평균 오차 87.8% | 프롬프트 설계 미흡 |

#### Phase 2: 모델 및 파라미터 최적화

```python
# Before
model = "gpt-4o-mini"
detail = "low"
temperature = 0.1

# After
model = "gpt-4o"
detail = "high"
temperature = 0.3
```

#### Phase 3: 시스템 메시지 추가

```python
{
    "role": "system",
    "content": """You are a professional logistics warehouse analyst.
    Your ONLY task is to analyze product packaging images to estimate
    physical logistics properties (weight, volume, category).
    This is a standard logistics industry task - NOT brand identification."""
}
```

- **효과**: 이미지 분석 거부율 40% → 5%

#### Phase 4: RAG 시스템 시도 (실패)

```python
# rag_builder.py
class RAGBuilder:
    def __init__(self):
        self.vectorstore = Chroma(embedding_function=OpenAIEmbeddings())

    def search_similar_products(self, category, k=3):
        return self.vectorstore.similarity_search(category, k=k)
```

**결과**:
- 평균 오차: 85.9% → **89.3%** (3.4%p 악화)
- **실패 원인**: 부적절한 유사도 매칭으로 무관한 예시 제공

#### Phase 5: Few-Shot Learning (성공)

**핵심 차이**: 수동으로 선별한 실패 케이스를 직접 프롬프트에 삽입

```
=== 실제 데이터 기반 중요 예시 (과거에 틀렸던 케이스들) ===

예시 1: 오뚜기 사골우거지국 (인스턴트 스프)
- 실제: 48g, 15.4x3.8x12.1cm
- ⚠️ 인스턴트 제품은 매우 가벼움! 과대예측 주의

예시 2: 박카스F액 10개입
- 실제: 2,704g, 22.9x14.5x9.4cm
- ⚠️ "x10", "*10" 표시 확인! 묶음 제품은 무거움

예시 3: SVEN 와플메이커
- 실제: 2,460g, 33.8x24.6x23.8cm
- ⚠️ 가전제품은 생각보다 무거움! 최소 1kg 이상
```

### 3.3 성능 변화

| 개선 단계 | 평균 무게 오차 | 변화 |
|----------|---------------|------|
| 초기 (gpt-4o-mini) | 87.8% | - |
| Phase 1 (gpt-4o) | 84.0% | -4.3%p |
| Phase 2 (시스템 메시지) | 84.0% | 안정성↑ |
| Phase 3 (프롬프트) | 85.9% | +1.9%p |
| **Phase 4 (RAG)** | **89.3%** | **+3.4%p (악화)** |
| **Phase 5 (Few-Shot)** | **42.3%** | **-47.0%p (대성공)** |

### 3.4 최종 성능 (물류 데이터 100개)

## 4. 방법론 2: Non-GPT (MASt3R + Image2Mass)

### 4.1 시스템 구성

```
┌──────────────────────────────────────────────────────────────────────────┐
│                    Non-GPT 예측 파이프라인                                 │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│   ┌──────────────┐    ┌─────────────────┐    ┌───────────────────────┐  │
│   │  다각도      │    │    MASt3R       │    │  Point Cloud          │  │
│   │  이미지      │ →  │  (NAVER Labs)   │ →  │  [N, 3]               │  │
│   │  (3장)       │    │  3D 복원        │    │  ※ 상대적 스케일만     │  │
│   └──────────────┘    └─────────────────┘    └───────────────────────┘  │
│                                                     │                    │
│                                                     ↓                    │
│                                              ┌───────────────┐           │
│                                              │ 치수 추출     │           │
│                                              │ L, W, H      │           │
│                                              └───────────────┘           │
│                                                     │                    │
│                                                     ↓                    │
│   ┌──────────────┐    ┌─────────────────┐    ┌───────────────────────┐  │
│   │  이미지      │    │   Image2Mass    │    │  무게 예측             │  │
│   │  (1장)       │ →  │   Xception      │ →  │  = 밀도 × 부피         │  │
│   │              │    │   backbone      │    │                        │  │
│   └──────────────┘    └─────────────────┘    └───────────────────────┘  │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.2 MASt3R 모델

**논문**: "MASt3R: Matching And Stereo 3D Reconstruction" (NAVER Labs Europe)

**특징**:
- Multi-view 3D 복원
- 카메라 파라미터 없이 동작
- Self-supervised learning

**한계**: **Metric Scale 복원 불가** (상대적 구조만)

### 4.3 Image2Mass 모델

**아키텍처**:
```
┌─────────────────────────────────────────┐
│ Input: 이미지 [B,3,H,W] + 치수 [B,3]   │
└─────────────────────────────────────────┘
                    │
                    ↓
┌─────────────────────────────────────────┐
│ Geometry Module (Xception backbone)     │
│   → Thickness Mask [B,1,19,19]          │
│   → 14D Geometric Features              │
└─────────────────────────────────────────┘
                    │
                    ↓
┌─────────────────────────────────────────┐
│ Density Tower (Xception + FC)           │
│   → Density Percentile [0,1]            │
└─────────────────────────────────────────┘
                    │
                    ↓
┌─────────────────────────────────────────┐
│ Volume Tower (FC)                       │
│   → Volume Prediction                   │
└─────────────────────────────────────────┘
                    │
                    ↓
         Output: Mass = Density × Volume
```

### 4.4 실험 조건

#### 조건 1: Full Pipeline (MASt3R + Image2Mass)
- MASt3R로 3D 복원 → 치수 추출 → Image2Mass

#### 조건 2: GT Volume (정답 치수 + Image2Mass)
- MASt3R 건너뛰고 정답 치수 직접 사용 → Image2Mass

### 4.5 성능 결과

#### MASt3R 부피 예측 성능 (100개)

| 지표 | 결과 |
|------|------|
| 부피 MAE | 4,015.1 cm³ |
| **부피 MAPE** | **100.0%** |
| L (길이) MAPE | 96.1% |
| W (너비) MAPE | 93.7% |
| H (높이) MAPE | 88.4% |

**분석**: 모든 샘플에서 약 90-100% 오차 → **스케일 추정 완전 실패**

#### 전체 무게 예측 성능 (100개)

| 방법 | 무게 MAE (g) | 무게 MAPE | 500g+ 오차 |
|------|-------------|----------|-----------|
| NonGPT (MASt3R) | 1,090.9 | 136.7% | 36.0% |
| **NonGPT + GT Volume** | **470.8** | 56.0% | **12.0%** |
| GPT-4o | 558.5 | **53.5%** | 16.0% |

### 4.6 MASt3R 스케일 문제 분석

**문제 원인**:
1. MASt3R는 **상대적 3D 구조**만 복원
2. **절대 스케일(metric scale)** 추정 불가
3. 참조 물체 없이는 실제 크기 알 수 없음

**해결 방안**:

| 방법 | 설명 | 장점 | 단점 |
|------|------|------|------|
| 참조 물체 | 알려진 크기 물체 포함 | 정확 | 촬영 환경 제약 |
| 학습 기반 | CNN으로 스케일 예측 | 추가 물체 불필요 | 학습 데이터 필요 |
| 카메라 파라미터 | focal length 활용 | 물리적 정확 | 캘리브레이션 필요 |
| **하이브리드** | GPT 카테고리 + 평균 크기 | 기존 시스템 활용 | 카테고리 의존 |

### 9.3 평가 지표 정의

```
MAE (Mean Absolute Error):
  = Σ|예측값 - 실제값| / N

MAPE (Mean Absolute Percentage Error):
  = Σ|예측값 - 실제값| / 실제값 × 100 / N

RMSE (Root Mean Square Error):
  = √(Σ(예측값 - 실제값)² / N)

500g+ 오차 비율:
  = |예측값 - 실제값| > 500g 인 샘플 비율
```
