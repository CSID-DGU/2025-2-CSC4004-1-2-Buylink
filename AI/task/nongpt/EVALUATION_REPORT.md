# 물류 무게/부피 예측 시스템 평가 보고서

## 1. 개요

본 보고서는 물류 입고물품의 무게 및 부피 예측을 위한 3가지 방식의 성능을 비교 분석합니다.

- **평가 데이터셋**: 물류공간 예측 데이터 (입고물품)
- **평가 샘플 수**: 100개 품목
- **평가 일시**: 2025-12-10

---

## 2. 평가 방법론

### 2.1 방법 1: NonGPT (MASt3R + Image2Mass)

**작동 원리:**
```
[여러 각도 이미지] → MASt3R 3D 복원 → 포인트 클라우드 → 치수(L,W,H) 추출 → Image2Mass → 무게 예측
```

1. **MASt3R (Matching and Stereo 3D Reconstruction)**
   - NAVER Labs에서 개발한 최신 multi-view 3D 복원 모델
   - 여러 각도의 이미지에서 dense 3D 포인트 클라우드 생성
   - 자가 지도 학습 기반으로 카메라 파라미터 없이 동작
   - 한계: metric scale이 정확하지 않음 (상대적 구조만 복원)

2. **치수 추출**
   - 포인트 클라우드에서 bounding box 계산
   - PCA 기반 주축 정렬 후 L, W, H 추출
   - 5~95 percentile outlier 제거

3. **Image2Mass 모델**
   - Xception 백본 기반 딥러닝 모델
   - Geometry Module: thickness mask 예측 + 14D geometric features
   - Density Tower: 이미지 특징 → 밀도 percentile 예측
   - Volume Tower: geometric features → 부피 예측
   - 최종 무게 = 밀도 × 부피

### 2.2 방법 2: NonGPT + GT Volume (Ground Truth 치수 사용)

**작동 원리:**
```
[이미지 1장] + [정답 치수(L,W,H)] → Image2Mass → 무게 예측
```

- MASt3R 3D 복원 단계를 건너뛰고, 라벨의 정확한 치수를 직접 입력
- Image2Mass 모델의 순수 성능 평가 목적
- 실제 환경에서는 치수 정보가 주어질 수 있음 (바코드 시스템 등)

### 2.3 방법 3: GPT Vision (GPT-4o)

**작동 원리:**
```
[이미지 1장] → GPT-4o Vision API → 카테고리/부피/무게 예측
```

1. **프롬프트 엔지니어링**
   - 물류 창고 관리 업무 컨텍스트 설정
   - 11개 대분류 카테고리 및 세부분류 가이드
   - 카테고리별 일반적인 무게 범위 제공
   - 과거 오류 케이스 예시로 학습 유도

2. **예측 과정**
   - 제품 식별 → 카테고리 분류 → 크기 추정 → 무게 계산
   - 패키지 라벨 정보 (용량, 중량 표시) 활용
   - 묶음 제품 (x10, x5 등) 인식

## 4. 분석 및 고찰

### 4.1 방법별 장단점

| 방법 | 장점 | 단점 |
|------|------|------|
| **NonGPT (MASt3R)** | 치수 정보 불필요, End-to-end | 스케일 추정 매우 부정확 (MAPE 115,868%), 계산 비용 높음 |
| **NonGPT + GT Volume** | API 비용 없음, 일관된 예측, **500g+ 오차 12%로 가장 낮음** | 정확한 치수 정보 필요 |
| **GPT-4o** | 카테고리 인식 우수, 라벨 정보 활용, **MAPE 53.5%로 가장 정확** | API 비용 발생 (~$2-3/100샘플), 대용량 제품 과소추정 |

### 4.2 핵심 발견

1. **MASt3R 스케일 문제가 가장 큰 한계**
   - 부피 MAPE 100%로 스케일 추정이 전혀 신뢰할 수 없음
   - 치수별로 L: 96.1%, W: 93.7%, H: 88.4% 오차
   - 참조 물체 없이는 절대 스케일 복원이 불가능

2. **치수 정보가 있을 때 NonGPT + GT Volume이 가장 안정적**
   - 500g+ 오차 비율 12%로 가장 낮음
   - API 비용 없음

3. **GPT-4o는 MAPE 기준 가장 정확**
   - 53.5%로 가장 낮은 평균 오차율
   - 라벨 인식 실패 시 큰 오차 발생 가능

### 4.3 MASt3R 스케일 문제 해결 방안

MASt3R는 상대적인 3D 구조만 복원하므로, 절대 스케일을 얻기 위한 방법이 필요합니다.

#### 방법 1: 참조 물체 사용 (Reference Object)
```
[이미지에 알려진 크기의 물체 포함] → 스케일 비율 계산 → 실제 치수 변환
```
- **장점**: 정확한 스케일 복원 가능
- **단점**: 촬영 환경에 참조 물체 필요 (자, 동전, A4용지 등)
- **구현**: 참조 물체 검출 → 픽셀/실제 크기 비율 → 포인트 클라우드 스케일링

#### 방법 2: 학습 기반 스케일 예측 (Learning-based)
```
[이미지 특징] → Scale Prediction Network → 스케일 팩터 예측
```
- **장점**: 추가 물체 불필요
- **단점**: 학습 데이터 필요, 일반화 어려움
- **구현**: CNN으로 이미지에서 스케일 팩터 직접 예측 (물체 카테고리 활용)

#### 방법 3: 카메라 파라미터 활용
```
[카메라 내부 파라미터 + 촬영 거리] → metric scale 복원
```
- **장점**: 물리적으로 정확
- **단점**: 카메라 캘리브레이션 필요, 촬영 거리 측정 필요
- **구현**: 카메라 focal length + 센서 크기 → 픽셀당 실제 크기 계산

#### 방법 4: 하이브리드 접근 (권장)
```
[MASt3R 상대 치수] + [GPT 카테고리 인식] → 카테고리별 평균 크기로 스케일 보정
```
- **장점**: 기존 시스템 활용, 추가 장비 불필요
- **단점**: 카테고리 내 크기 편차에 의존
- **구현**:
  1. GPT로 제품 카테고리 인식
  2. 카테고리별 평균 크기 데이터베이스 구축
  3. MASt3R 상대 치수 비율 유지하며 스케일 조정

### 4.4 개선 방향

1. **NonGPT 방식**
   - 스케일 보정 모듈 필수 (위 방법 중 선택)
   - 현재 상태로는 실용성 낮음

2. **GPT 방식**
   - Few-shot 예시 추가 (특히 대용량 제품)
   - 라벨 OCR 연동으로 용량 정보 정확도 향상

## 부록 A: 모델 구조

### Image2Mass 모델 아키텍처

```
Input: 이미지 [B,3,H,W] + 치수 [B,3]
         ↓
┌─────────────────────────────────────────┐
│ Geometry Module (Xception backbone)     │
│   → Thickness Mask [B,1,19,19]          │
│   → 14D Geometric Features              │
└─────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│ Density Tower (Xception + FC)           │
│   → Density Percentile [0,1]            │
│   → 16D Hidden Features                 │
└─────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│ Volume Tower (FC)                       │
│   → Volume Prediction                   │
└─────────────────────────────────────────┘
         ↓
Output: Mass = Density × Volume
```

### MASt3R 3D 복원 파이프라인

```
Input: N장의 이미지
         ↓
┌─────────────────────────────────────────┐
│ Image Pair Inference (ViT encoder)      │
│   → N×(N-1)/2 pair-wise predictions     │
└─────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│ Global Alignment (Bundle Adjustment)    │
│   → Camera poses + Depth maps           │
└─────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│ Point Cloud Generation                  │
│   → Dense 3D points with confidence     │
└─────────────────────────────────────────┘
         ↓
Output: Point Cloud [N, 3] + 치수 (L, W, H)
        ※ 스케일은 상대적 (metric scale 아님)
```

## 부록 B: 스케일 보정 구현 예시

### 참조 물체 기반 스케일 보정

```python
def scale_correction_with_reference(pts3d, reference_detected_size, reference_real_size):
    """
    참조 물체를 이용한 스케일 보정

    Args:
        pts3d: MASt3R 포인트 클라우드 [N, 3]
        reference_detected_size: 검출된 참조 물체 크기 (MASt3R 스케일)
        reference_real_size: 실제 참조 물체 크기 (cm)

    Returns:
        scaled_pts3d: 실제 스케일로 변환된 포인트 클라우드
    """
    scale_factor = reference_real_size / reference_detected_size
    scaled_pts3d = pts3d * scale_factor
    return scaled_pts3d
```

### 카테고리 기반 스케일 예측

```python
# 카테고리별 평균 크기 데이터베이스
CATEGORY_AVG_DIMS = {
    "음료/생수": {"L": 25, "W": 15, "H": 20},
    "과자류": {"L": 30, "W": 20, "H": 10},
    "조미료": {"L": 15, "W": 10, "H": 20},
    # ...
}

def scale_correction_with_category(pts3d, category, detected_dims):
    """
    카테고리 평균 크기를 이용한 스케일 보정
    """
    avg_dims = CATEGORY_AVG_DIMS.get(category)
    if avg_dims is None:
        return pts3d  # 보정 불가

    # 비율 유지하며 스케일 조정
    avg_volume = avg_dims["L"] * avg_dims["W"] * avg_dims["H"]
    detected_volume = detected_dims["L"] * detected_dims["W"] * detected_dims["H"]

    scale_factor = (avg_volume / detected_volume) ** (1/3)
    scaled_pts3d = pts3d * scale_factor
    return scaled_pts3d
```
